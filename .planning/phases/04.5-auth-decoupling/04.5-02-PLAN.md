**Create `apps/dashboard/src/app/api/auth/nonce/route.ts`:**
- Export `GET` handler
- Import `generateSiweNonce` from `viem/siwe`
- Import `getSession` from `@/lib/session`
- Generate nonce via `generateSiweNonce()`
- Store nonce in iron-session cookie: `session.nonce = nonce; await session.save();`
- Return nonce as plain text: `new NextResponse(nonce, { headers: { "Content-Type": "text/plain" } })`
- The nonce is temporary — it lives in the cookie only until /api/auth/verify consumes it

**Create `apps/dashboard/src/app/api/auth/verify/route.ts`:**
- Export `POST` handler accepting `{ message: string, signature: string }` in JSON body
- Import `parseSiweMessage` from `viem/siwe` and `keccak256`, `toHex` from `viem`
- Import `luksoPublicClient` from `@/lib/web3/client`
- Import `getSession`, `createSession` from `@/lib/session`
- Flow:
  1. Parse JSON body: `const { message, signature } = await request.json()`
  2. Parse SIWE message: `const siweMessage = parseSiweMessage(message)`
  3. Read nonce from iron-session cookie: `const session = await getSession()`
  4. Verify nonce matches: `if (siweMessage.nonce !== session.nonce) return 422`
  5. Verify signature using `luksoPublicClient.verifySiweMessage({ message, signature })` — this handles EIP-1271 for UP smart contract accounts automatically
  6. If invalid: return `{ ok: false }` with 401
  7. Compute messageHash: `keccak256(toHex(message))`
  8. Compute expiresAt from `siweMessage.expirationTime` — if present use its ISO string, otherwise default to 2 hours from now
  9. Call `createSession({ address: siweMessage.address!, signature, message, messageHash, expiresAt })`
  10. Return `{ ok: true }` with 200
- Wrap in try/catch, log errors with `console.error("[auth] SIWE verification failed:", error)`, return 500

**Create `apps/dashboard/src/app/api/auth/logout/route.ts`:**
- Export `POST` handler
- Import `destroySession` from `@/lib/session`
- Call `await destroySession()`
- Return `{ ok: true }` with 200
- Note: This is called by RainbowKit's auth adapter signOut callback AND by the sidebar logoutAction (which uses the server action pattern)

**Create `apps/dashboard/src/app/api/auth/me/route.ts`:**
- Export `GET` handler
- Import `getSessionData` from `@/lib/session`
- Call `const sessionData = await getSessionData()`
- If no session: return `{ address: null }` with 200
- If session exists: return `{ address: sessionData.address }` with 200
- This endpoint is polled by the RainbowKit auth adapter to check authentication status on page load and window focus

**Rewrite `apps/dashboard/src/lib/auth/actions.ts`:**

1. **Remove** all Proxmox-related imports:
   - `import { login } from "@/lib/proxmox/auth"`
   - `import { DatabaseService } from "@/lib/db"`
   - `import { encrypt } from "@/lib/encryption"`
   - `import { ProxmoxClient } from "@/lib/proxmox/client"`
   - `import { listNodes } from "@/lib/proxmox/nodes"`

2. **Remove** the `loginSchema` Zod schema

3. **Remove** the entire `loginAction` (server action that authenticated against Proxmox ticket API)

4. **Remove** the entire `ensureNodeExists` helper function (auto-provisioned nodes on Proxmox login)

5. **Keep** the `logoutAction` — simplify it:
   ```typescript
   "use server";

   import { redirect } from "next/navigation";
   import { authActionClient } from "@/lib/safe-action";
   import { destroySession } from "@/lib/session";

   /**
    * Logout action — destroys the session and redirects to login.
    * Uses authActionClient since the user must be authenticated to log out.
    */
   export const logoutAction = authActionClient.action(async () => {
     await destroySession();
     redirect("/login");
   });
   ```

6. **Keep** the `"use server"` directive at top

7. The file should be ~15 lines total. No Proxmox imports, no login logic, no node provisioning. Just logout.

**Why remove loginAction entirely:** Authentication now happens through the client-side RainbowKit flow → /api/auth/verify API route. There is no server action for login. The user connects their Universal Profile via the RainbowKit modal, signs a SIWE message client-side, and the signature is verified server-side via the API route.

**Why keep logoutAction as authActionClient:** The sidebar logout button still uses `useAction(logoutAction)`. The server action destroys the Redis session and iron-session cookie, then redirects. This pattern is unchanged.
