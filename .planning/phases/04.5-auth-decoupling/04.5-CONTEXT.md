# Phase 04.5: Auth Decoupling — RainbowKit + Universal Profiles

## Vision

Replace the current Proxmox-coupled login flow with Web3 wallet authentication using RainbowKit, restricted to Universal Profiles (LUKSO) only. Users connect their Universal Profile to sign in, then add Proxmox nodes as a post-login configuration step.

**Current flow:** Login page → authenticate against Proxmox ticket API → auto-provision node → dashboard
**Target flow:** Login page → RainbowKit connect (UP only) → SIWE sign → dashboard → add nodes in settings

## User Decisions

### Authentication Model
- **RainbowKit with Universal Profile only** — no generic wallet support (MetaMask, etc.)
- Sign-In with Ethereum (SIWE) standard
- User identity = Universal Profile address (e.g., `0x1234...abcd`)

### Session Model
- Store in Redis: **signature + message + message hash**
- Session expiry derived from the SIWE message's `expirationTime` field
- Iron-session cookie still holds session ID pointing to Redis data
- No Proxmox ticket/CSRF in session — those live on node records

### Proxmox Node Storage
- Nodes stored per connected Universal Profile address
- `ProxmoxNode.userId` migrated from Proxmox username to UP wallet address
- Each node stores its own Proxmox auth credentials (API token or username/password)
- Node authentication is independent of user session — user proves identity via UP, then node credentials handle Proxmox API access

### User Identity Migration
- Current: `userId` = Proxmox username (e.g., `root@pam`)
- Target: `userId` = Universal Profile address (e.g., `0x1234...abcd`)
- This touches: session, middleware, authActionClient, DatabaseService, all server actions, data layer

## What Must Change

### Remove
- Proxmox ticket API authentication in loginAction
- `ticket`, `csrfToken`, `realm`, `host`, `port` from RedisSessionData
- Login page form (host, port, username, password, realm fields)
- `getProxmoxCredentials()` helper in session.ts
- Auto-provisioning of Proxmox node on login

### Add
- RainbowKit provider + wagmi config (Universal Profile chain + connector)
- SIWE authentication flow (nonce → sign → verify → session)
- New RedisSessionData: `{ address, signature, message, messageHash, expiresAt }`
- Connect wallet UI on login page (RainbowKit modal)
- SIWE API routes: `/api/auth/nonce`, `/api/auth/verify`, `/api/auth/logout`

### Modify
- `getSessionData()` returns UP address instead of Proxmox username
- `authActionClient` ctx provides UP address as userId
- Middleware checks session cookie validity (same mechanism, different session shape)
- `ProxmoxNode.userId` column data migration (Proxmox username → wallet address)
- All `session.username` references → `session.address`
- Node settings page: must include Proxmox credentials (username/password or API token) since login no longer provides them

## What Stays the Same

- Iron-session + Redis session architecture (just different payload)
- Middleware cookie check pattern (Edge-safe)
- `authActionClient` pattern (just different userId source)
- All container operations, template system, wizard, dashboard
- Node CRUD server actions (already exist from 03.5-03)
- Settings page structure (/settings/nodes)

## Technical Constraints

- RainbowKit requires `"use client"` — all wallet interaction is client-side
- SIWE verification must happen server-side (API route, not server action)
- Universal Profile connector may need custom RainbowKit wallet adapter
- wagmi v2 + viem for chain/wallet config
- LUKSO mainnet chain ID: 42 (or testnet: 4201)

## Out of Scope

- Multi-wallet support (only Universal Profiles)
- On-chain storage of node configs (stays in PostgreSQL)
- Smart contract interactions beyond SIWE
- ENS or other name resolution
