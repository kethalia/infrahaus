## Decisions Made

1. **WalletButton with wallet="universal-profiles"** — Instead of generic ConnectButton, targets the specific wallet for cleaner UX and a focused connection modal
2. **Fallback projectId ("MISSING_PROJECT_ID")** — Prevents module-load crash when NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID env var is empty; app starts and shows meaningful error instead of failing at import time
3. **useRedirectOnAuth polls /api/auth/me** — Instead of checking wagmi `isConnected`, polls the server session endpoint. This prevents a redirect loop where `isConnected` fires before the SIWE verify endpoint completes, causing the user to redirect before their session cookie is set
4. **Pre-existing Zod v3→v4 type incompatibility** — Build failure in 6 files from `@hookform/resolvers` using Zod v3 types while project uses Zod v4. Not introduced by this plan, tracked as known issue

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] WalletConnect projectId crash on empty env var**
- **Found during:** Post-checkpoint UAT
- **Issue:** When NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID is empty string or undefined, WalletConnect SDK throws at module load time, crashing the entire login page
- **Fix:** Added fallback projectId ("MISSING_PROJECT_ID") in web3/config.ts — app loads gracefully, WalletConnect just fails to connect (which is expected without a real ID)
- **Files modified:** apps/dashboard/src/lib/web3/config.ts
- **Committed in:** `427c520`

**2. [Rule 1 - Bug] Generic ConnectButton showing all wallets instead of Universal Profiles only**
- **Found during:** Post-checkpoint UAT
- **Issue:** ConnectButton showed MetaMask, Coinbase, and other wallets. Plan required Universal Profile-only connection
- **Fix:** Switched to `WalletButton` component with `wallet="universal-profiles"` prop for targeted wallet selection
- **Files modified:** apps/dashboard/src/app/login/page.tsx
- **Committed in:** `2036a2b`

**3. [Rule 1 - Bug] Redirect loop when using wagmi isConnected for auth state**
- **Found during:** Post-checkpoint UAT
- **Issue:** Login page used `useAccount().isConnected` to trigger redirect to dashboard. But `isConnected` becomes true when wallet connects, BEFORE the SIWE verify endpoint creates the server session. This caused redirect to dashboard without a session cookie, which middleware then redirected back to login
- **Fix:** Created `useRedirectOnAuth` hook that polls `/api/auth/me` endpoint to check for actual server session before redirecting
- **Files modified:** apps/dashboard/src/app/login/page.tsx
- **Committed in:** `a3a4bc6`
