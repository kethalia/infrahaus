**Add per-node timeout (~5s) and error tracking to `getContainersWithStatus()`:**
After Plan 03's rewrite, the function fetches Proxmox containers from all nodes in parallel
with per-node error isolation. Currently it catches per-node errors silently.

CONTEXT requires: "~5s timeout per node, skip unresponsive nodes."

First, add a constant to `timeouts.ts`:
```typescript
/** Per-node timeout for Proxmox container list fetches (ms) */
export const PROXMOX_NODE_TIMEOUT_MS = 5_000;
```

Then enhance the per-node fetch with timeout AND error tracking:

```typescript
import { PROXMOX_NODE_TIMEOUT_MS } from "@/lib/constants/timeouts";

const failedNodes: string[] = [];

// Inside the per-node Promise.all map, wrap with AbortSignal.timeout:
const results = await Promise.all(
  userNodes.map(async (dbNode) => {
    try {
      const client = await createSessionClient(dbNode);
      const containers = await listContainers(client, dbNode.name, {
        signal: AbortSignal.timeout(PROXMOX_NODE_TIMEOUT_MS),
      });
      return containers;
    } catch (error) {
      console.error(`Node ${dbNode.name} container list failed:`, error);
      failedNodes.push(dbNode.name);
      return [];
    }
  }),
);
```

NOTE: If `listContainers` doesn't accept an AbortSignal, use `Promise.race` instead:
```typescript
const fetchWithTimeout = Promise.race([
  listContainers(client, dbNode.name),
  new Promise<never>((_, reject) =>
    setTimeout(() => reject(new Error(`Node ${dbNode.name} timed out`)), PROXMOX_NODE_TIMEOUT_MS)
  ),
]);
```

Update the return type to include `failedNodes`:
```typescript
export interface ContainersPageData {

  counts: { total: number; running: number; stopped: number; error: number };
  proxmoxReachable: boolean;
  failedNodes: string[];  // Names of nodes that failed to respond
}
```

Return `failedNodes` from the function. Set `proxmoxReachable = false` only when
ALL nodes fail (i.e., `failedNodes.length === userNodes.length && userNodes.length > 0`).
