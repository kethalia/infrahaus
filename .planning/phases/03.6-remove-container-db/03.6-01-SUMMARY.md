# Phase 3.6 Plan 01: Redis Creation State Module Summary

**Redis-based creation lifecycle module with SET-tracked active jobs, tiered TTLs, and pipeline-atomic CRUD — foundation for replacing DB Container model**

## Accomplishments

### Task 1: Creation State Constants

Added 4 constants to `infrastructure.ts`:
- `CREATION_JOB_KEY_PREFIX` — Redis key prefix for per-VMID creation jobs
- `ACTIVE_CREATIONS_SET` — Redis SET name for tracking active creations
- `CREATION_TTL_ACTIVE_S` — 24h TTL for actively-creating jobs
- `CREATION_TTL_COMPLETE_S` — 1h TTL for completed/errored jobs

### Task 2: Redis State Module

Created `redis-state.ts` (239 lines) with:

**Types:**
- `CreationLifecycle` — "creating" | "ready" | "error" (replaces Prisma enum)
- `CreationJob` — Full creation record (vmid, nodeId, nodeName, templateId, hostname, lifecycle, createdAt, errorMessage)

**Functions (6):**
1. `getCreationKey(vmid)` — Build Redis key from VMID
2. `storeCreationJob(redis, job)` — Pipeline SET+SADD with 24h TTL
3. `getCreationJob(redis, vmid)` — Single key GET+parse
4. `updateCreationLifecycle(redis, vmid, lifecycle, errorMessage?)` — Transition state, adjust TTL, remove from active set if terminal
5. `deleteCreationJob(redis, vmid)` — Pipeline DEL+SREM
6. `listActiveCreations(redis)` — SET-based listing with pipeline GET and stale member cleanup

**Design decisions:**
- No `server-only` guard — worker process imports this module
- Redis instance as first parameter (not `getRedis()` internally) — matches vmid-cache.ts pattern, enables testing
- Pipeline operations for atomicity (SET+SADD, DEL+SREM)
- Fire-and-forget SREM for stale set members in listActiveCreations
