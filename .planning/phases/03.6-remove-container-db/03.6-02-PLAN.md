**Queue types (`lib/queue/container-creation.ts`):**

Update `ContainerJobData`:

**createContainerAction (`lib/containers/actions.ts`):**

Replace the entire container creation block. Currently it:
1. Calls `DatabaseService.createContainer()` — creates DB record
2. Has a complex P2002 unique violation handler for stale records
3. Returns `{ containerId: container.id }` (cuid)

New flow:
1. Check Redis creation state: `getCreationJob(redis, data.vmid)` — if exists with lifecycle "creating", reject with "VMID has an active creation in progress"
2. Check VMID cache: `isVmidTaken(nodeId, data.vmid)` — if taken, reject (already done by wizard, but server-side guard)
3. Store creation state: `storeCreationJob(redis, { vmid: data.vmid, nodeId, nodeName, templateId: data.templateId || null, hostname: data.hostname, lifecycle: "creating", createdAt: new Date().toISOString() })`
4. Enqueue BullMQ job — same as before but without `containerId` in job data (vmid is in config)
5. Invalidate VMID cache — same as before
6. Return `{ vmid: data.vmid }` instead of `{ containerId: container.id }`

Import `getRedis` from `@/lib/redis` and `storeCreationJob`, `getCreationJob` from `@/lib/containers/redis-state`.

Remove imports: `DatabaseService` from `@/lib/db` (for container creation only — keep if still used by other functions in this file like `getContainerContext`), `prisma` (if only used for container stale-record check).

**IMPORTANT:** The `getWizardData` function in this same file still uses `prisma.template.findMany()` and `DatabaseService.getDefaultNodeForUser()` etc. DO NOT remove those imports. Only remove Container-specific DB usage.

Update `checkVmidAction` and `refreshVmidCacheAction` — no changes needed (they use VMID cache, not Container model).

**getContainerContext (`lib/containers/actions.ts`):**

Currently supports two paths:
1. `containerId.startsWith("pve-")` — Proxmox-only path (searches user nodes)
2. Default — DB lookup via `DatabaseService.getContainerById()`

After migration, ALL containers use the Proxmox path:
1. Parse vmid from containerId: `const vmid = parseInt(containerId, 10)`
2. If NaN, throw ActionError
3. Get user nodes: `DatabaseService.listNodesForUser(userId)` (userId comes from ctx)
4. For each node, try to find the container via Proxmox API (same as current pve- path)
5. Return `{ client, nodeName, vmid, nodeId }` — remove `container` field from return type

**CRITICAL:** The `userId` parameter is now REQUIRED for `getContainerContext`. Currently the pve- path requires it but the DB path doesn't. Update the function signature to make userId required (not optional). All callers already pass `ctx.userId`.

Remove the `container` field from the return value entirely. Update all lifecycle actions that check `if (container)` for DB event creation — remove those blocks.

**Lifecycle actions (start, stop, shutdown, restart, delete):**

For each action (startContainerAction, stopContainerAction, shutdownContainerAction, restartContainerAction):
- Remove the `if (container) { await DatabaseService.createContainerEvent({...}) }` blocks
- The rest of the logic stays the same (Proxmox API calls, lock management, revalidation)

For `deleteContainerAction`:
- Remove `if (container) { ... DatabaseService.deleteContainerById() }` block
- Add: `await deleteCreationJob(redis, vmid)` to clean up any Redis creation state
- Keep Redis cleanup: `clearCachedServices`, log buffer deletion
- These Redis cleanups should ALWAYS run (not gated by `if (container)`)
- Import `deleteCreationJob` from `@/lib/containers/redis-state`
- Import `getRedis` from `@/lib/redis` at the top of the action (or use dynamic import pattern)

**refreshContainerServicesAction:**
- Uses `getContainerContext` which will now always use Proxmox path — no changes needed to the action itself
- The `containerId` parameter is a string (vmid as string from URL) — works as-is

Completely remove the DB event persistence block (lines ~97-129 in current code). Keep ONLY:
- Redis Pub/Sub publish
- Redis ring buffer (rpush + ltrim + expire)

The function signature changes: `publishProgress(vmid: number, event: ...)` — use `String(vmid)` internally for Redis keys.

Or simpler: keep `publishProgress(containerId: string, event)` signature and have the caller pass `String(vmid)`. This minimizes changes.
