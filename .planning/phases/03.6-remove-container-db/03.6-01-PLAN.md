**No `server-only`** — the worker process (runs outside Next.js via tsx) must import this module.
Add a comment: `// No "server-only" — used by worker process`

**Types:**
```typescript
/** Container creation lifecycle — replaces Prisma ContainerLifecycle enum */
export type CreationLifecycle = "creating" | "ready" | "error";

/** Creation job stored in Redis — replaces DB Container model for in-progress jobs */
export interface CreationJob {
  vmid: number;
  nodeId: string;
  nodeName: string;
  templateId: string | null;
  hostname: string;
  lifecycle: CreationLifecycle;
  createdAt: string; // ISO 8601
  errorMessage?: string;
}
```

**Functions (all take a Redis instance as first param — same pattern as vmid-cache.ts):**

1. `getCreationKey(vmid: number): string` — returns `${CREATION_JOB_KEY_PREFIX}${vmid}`

2. `storeCreationJob(redis: Redis, job: CreationJob): Promise<void>`
   - Pipeline: SET the job JSON with CREATION_TTL_ACTIVE_S expiry + SADD vmid to ACTIVE_CREATIONS_SET
   - Use `redis.pipeline()` for atomicity

3. `getCreationJob(redis: Redis, vmid: number): Promise<CreationJob | null>`
   - GET the key, parse JSON, return null if not found

4. `updateCreationLifecycle(redis: Redis, vmid: number, lifecycle: CreationLifecycle, errorMessage?: string): Promise<void>`
   - GET existing job (return early if null — job already expired)
   - Update lifecycle and optional errorMessage
   - SET with appropriate TTL: CREATION_TTL_COMPLETE_S for "ready", CREATION_TTL_COMPLETE_S for "error" (both 1h per CONTEXT)
   - If lifecycle is "ready" or "error", SREM from ACTIVE_CREATIONS_SET (no longer active)

5. `deleteCreationJob(redis: Redis, vmid: number): Promise<void>`
   - Pipeline: DEL the key + SREM from ACTIVE_CREATIONS_SET

6. `listActiveCreations(redis: Redis): Promise<CreationJob[]>`
   - SMEMBERS on ACTIVE_CREATIONS_SET to get vmid strings
   - If empty, return []
   - Pipeline GET for each vmid's creation key
   - Filter results: keep jobs that parsed successfully AND have lifecycle "creating"
   - Clean up stale set members: for any vmid where the key is missing (expired) or lifecycle is not "creating", SREM from the set
   - Return filtered CreationJob array

Import `Redis` type from `ioredis` (same as vmid-cache.ts pattern).
Import constants from `@/lib/constants/infrastructure`.

**IMPORTANT:** Do NOT use `redis.keys()` — it's O(N) and blocks Redis. The ACTIVE_CREATIONS_SET pattern avoids this.
