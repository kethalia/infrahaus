# Phase 04.6 Plan 01: Pool-Based Proxmox Access Control

## Objective

Wire the Proxmox resource pool through the entire container creation pipeline so each dashboard user's containers are isolated in their own pool. This enables least-privilege API tokens that can only manage containers they created, which is critical for shared Proxmox nodes.

## Context

@apps/dashboard/prisma/schema.prisma
@apps/dashboard/src/lib/nodes/schemas.ts
@apps/dashboard/src/lib/db.ts
@apps/dashboard/src/components/nodes/node-form-dialog.tsx
@apps/dashboard/src/lib/queue/container-creation.ts

@apps/dashboard/src/lib/containers/actions.ts
@apps/dashboard/src/lib/proxmox/containers.ts
@apps/dashboard/docs/proxmox-api-token-setup.md

## Background

The Proxmox API already accepts a `pool` parameter on container creation (`POST /nodes/{node}/lxc`), and our `createContainer()` function in `proxmox/containers.ts` already handles `config.pool`. But the `pool` value is never set because:

1. `ProxmoxNode` model has no `pool` column
2. Node schemas don't include `pool`
3. Node form UI has no pool input
4. `ContainerJobData.config` has no `pool` field
5. Worker doesn't read pool from anywhere
6. `createContainerAction` doesn't pass pool to the job

This plan wires pool end-to-end.
