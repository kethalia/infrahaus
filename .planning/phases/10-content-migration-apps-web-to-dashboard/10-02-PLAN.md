# Plan 10-02: Verify Links, Build, and Navigation Structure

## Goal

Confirm that the migrated documentation content builds successfully in the dashboard, all internal `/docs/` links resolve to existing files, and the Fumadocs sidebar navigation reflects the correct section ordering from meta.json.

## must_haves

- [ ] `pnpm --filter dashboard exec tsc --noEmit` exits with code 0
- [ ] `pnpm --filter dashboard lint` exits with code 0
- [ ] `NEXT_SKIP_TYPE_CHECK=1 pnpm --filter dashboard build` exits with code 0
- [ ] All internal `/docs/` link targets found in MDX content exist as files in `apps/dashboard/content/docs/`
- [ ] No build errors related to MDX parsing or Fumadocs source loader

## Tasks

<task id="10-02-01">
<title>Verify all internal /docs/ links resolve to existing files</title>
<instructions>
Extract all internal `/docs/` hrefs from the migrated MDX files and verify each target path exists as a file in the content directory.

Run the following to list all unique internal doc links:

```bash
grep -roh '(/docs/[^)"'"'"'#\s]*)' apps/dashboard/content/docs/ --include="*.mdx" | sort -u
```

For each link of the form `/docs/section/page`, verify the file `apps/dashboard/content/docs/section/page.mdx` exists. Since all linked pages are part of the 29-file migration, any missing file indicates an incomplete copy that must be fixed by re-running the cp command from plan 10-01.

A quick structural check — if `diff -rq` returned empty in 10-01-02, all link targets are guaranteed to exist (every file in apps/web that is linked is also in apps/dashboard). Confirm this invariant holds.
</instructions>
<automated>
grep -roh '(/docs/[^)"'"'"'#\s]*)' apps/dashboard/content/docs/ --include="*.mdx" | sort -u
</automated>
</task>

<task id="10-02-02">
<title>Run TypeScript check and lint</title>
<instructions>
Run TypeScript type checking and ESLint on the dashboard to confirm no type errors or lint violations were introduced by the content migration.

```bash
pnpm --filter dashboard exec tsc --noEmit
pnpm --filter dashboard lint
```

Both commands must exit with code 0. Since Phase 10 adds only MDX/JSON content files and makes no TypeScript source changes, failures here indicate a pre-existing issue unrelated to the migration.
</instructions>
<automated>

</automated>
</task>

<task id="10-02-03">
<title>Run production build to verify Fumadocs discovers all 29 pages</title>
<instructions>
Run the Next.js production build for the dashboard. This triggers Fumadocs MDX compilation and `generateStaticParams()` which must enumerate all 29 doc pages. A successful build confirms:

- All 29 MDX files parse without errors
- Fumadocs source loader discovers all pages from the content tree
- All section routes are statically generated
- The search index is built from all migrated pages

```bash
NEXT_SKIP_TYPE_CHECK=1 pnpm --filter dashboard build
```

Expected: build completes with exit code 0. If the build fails with MDX parse errors, check whether the cp command in 10-01 corrupted any files (re-run diff to verify).
</instructions>
<automated>

</automated>
</task>
