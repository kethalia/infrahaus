# Plan 13-02: Docker-Compose Service Browser

## Goal

Add a read-only `/infra` catalog page to the dashboard that lists all infra services (docker-compose, LXC, Terraform) with links to their docs, and add an "Infra" nav item to the sidebar between Templates and Documentation.

> **Note on `infra/docker/`:** The `infra/docker/` directory contains Docker Engine installation scripts (getting-started tooling, not a user-facing service). It is not represented as a catalog service entry — Docker installation is covered by the existing getting-started docs and is a prerequisite for other services, not a standalone infra service. No catalog entry or additional docs page is needed for this phase.

## must_haves

- [ ] `apps/dashboard/src/lib/infra/catalog.ts` exists with a typed `InfraService` interface and an `INFRA_CATALOG` array covering all seven infra categories (ai, media, gaming, blockchain, deployment, networking, development)
- [ ] `apps/dashboard/src/app/(dashboard)/infra/page.tsx` renders an `InfraServiceCard` for each catalog entry — page loads at `/infra` without a 500 error
- [ ] `apps/dashboard/src/components/infra/infra-service-card.tsx` uses shadcn `Card`, `Badge`, and `Button` components (no custom div wrappers for card patterns)
- [ ] `apps/dashboard/src/components/app-sidebar.tsx` includes an "Infra" nav item with `href: "/infra"` and `Server` icon from lucide-react, placed between "Packages" and "Documentation"
- [ ] `pnpm --filter dashboard exec tsc --noEmit` exits 0 after all files are created
- [ ] Breadcrumbs on `/infra` show "Infra" correctly via the `(dashboard)` layout breadcrumb mechanism — no custom breadcrumb code is needed for this route

<task id="13-02-02" title="Create InfraServiceCard component">
<context>The service card renders one `InfraService` entry. It must use shadcn Card, Badge, and Button components per the CLAUDE.md shadcn-first rule. The TemplateCard at `apps/dashboard/src/components/templates/template-card.tsx` is the model to follow for card layout conventions. The card shows: service name, description, deploy type badge, GPU badge (if applicable), a list of service names, and a "View Docs" button linking to the docsPath. Cards without a docsPath omit the button.</context>
<steps>
1. Create directory `apps/dashboard/src/components/infra/`
2. Create `apps/dashboard/src/components/infra/infra-service-card.tsx` as a server component (no `"use client"` directive needed — no client interactivity)
3. Import `Card`, `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, `CardFooter` from `@/components/ui/card`
4. Import `Badge` from `@/components/ui/badge`
5. Import `Button` from `@/components/ui/button`
6. Import `Link` from `next/link`
7. Import `InfraService` type from `@/lib/infra/catalog`
8. Component signature: `export function InfraServiceCard({ service }: { service: InfraService })`
9. Layout:
   - `CardHeader`: `CardTitle` with service name; `CardDescription` with description
   - `CardContent`: Row of badges — one for `deployType` (variant `"outline"`), one for `"GPU Required"` (variant `"destructive"`) shown only when `requiresGpu === true`, one per tag using `service.tags` (variant `"secondary"`)
   - Below badges: small text listing `service.services.join(", ")` with a muted label "Services:"
   - `CardFooter`: `Button` as `Link` pointing to `service.docsPath` (only rendered if `service.docsPath` is defined), label "View Docs"
</steps>
