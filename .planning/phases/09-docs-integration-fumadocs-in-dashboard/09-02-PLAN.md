<file>apps/dashboard/src/app/(docs)/docs.css</file>
<instructions>
Create the file `apps/dashboard/src/app/(docs)/docs.css`. This file imports Fumadocs UI CSS and will be imported ONLY in the (docs) layout — not in the root `globals.css`. This isolates Fumadocs styles from the dashboard pages.

Note: In Next.js, CSS files imported in a layout are technically global in scope (CSS is not component-scoped), but placing this import only in the (docs) layout ensures it is only loaded for doc routes in the browser's critical CSS path. The Fumadocs `neutral` preset uses `--fd-*` prefixed CSS custom properties which do not conflict with the dashboard's `--*` (shadcn-compatible) variables.

File content:

```css
@import "fumadocs-ui/css/neutral.css";
@import "fumadocs-ui/css/preset.css";
```
</instructions>

<title>Create docs layout: apps/dashboard/src/app/(docs)/docs/layout.tsx</title>
<file>apps/dashboard/src/app/(docs)/docs/layout.tsx</file>
<instructions>
Create the file `apps/dashboard/src/app/(docs)/docs/layout.tsx`. This is the layout for all /docs/* routes. It must:

1. Import the Fumadocs CSS (from the sibling `docs.css` in the parent `(docs)` directory)
2. Wrap children with `RootProvider` from `fumadocs-ui/provider` (scoped to docs routes only — NOT added to root layout)
3. Render `DocsLayout` from `fumadocs-ui/layouts/docs` with the page tree from source

The `RootProvider` scoped here handles Fumadocs theming, search dialog state, and the dark/light toggle. It does not conflict with the existing dashboard layout because `(docs)` and `(dashboard)` are sibling route groups — only one layout renders per request.

File content:

```tsx
import "../docs.css";
import { RootProvider } from "fumadocs-ui/provider";
import { DocsLayout } from "fumadocs-ui/layouts/docs";
import { source } from "@/lib/source";
import type { ReactNode } from "react";

export default function Layout({ children }: { children: ReactNode }) {
  return (
    <RootProvider>
      <DocsLayout tree={source.getPageTree()} nav={{ title: "Infrahaus Docs" }}>
        {children}
      </DocsLayout>
    </RootProvider>
  );
}
```

The relative import `"../docs.css"` resolves from `src/app/(docs)/docs/layout.tsx` up one level to `src/app/(docs)/docs.css`. This is correct.
</instructions>

<task id="09-02-03" type="edit">
<title>Add suppressHydrationWarning to root layout &lt;html&gt;</title>
<file>apps/dashboard/src/app/layout.tsx</file>
<instructions>
Edit `apps/dashboard/src/app/layout.tsx` to add `suppressHydrationWarning` to the `<html>` element.

Without this attribute, `next-themes` and Fumadocs' `RootProvider` will cause React hydration warnings in the browser when the dark mode class is applied server-side vs client-side. This is a standard requirement for any Next.js app that uses theme toggling.

Change:
```tsx
    <html lang="en">
```

To:
```tsx
    <html lang="en" suppressHydrationWarning>
```

No other changes to the root layout are needed. Do NOT add `RootProvider` or any Fumadocs imports to the root layout — those stay scoped to the (docs) layout.
</instructions>

<title>Create search API route: apps/dashboard/src/app/api/search/route.ts</title>
<file>apps/dashboard/src/app/api/search/route.ts</file>
<instructions>
Create the file `apps/dashboard/src/app/api/search/route.ts`. This route handler provides full-text search for the Fumadocs search dialog.

The search route is protected by the existing middleware (all routes except `/login`, `/_next/*`, and `/api/auth/*` require authentication). This is intentional — docs are auth-gated, so search is also auth-gated. No middleware changes are needed.

This is a direct copy of `apps/web/app/api/search/route.ts`, adapted with the `@/lib/source` path (which resolves to `src/lib/source.ts` in the dashboard via the `@/*` alias).

File content:

```ts
import { source } from "@/lib/source";
import { createSearchAPI } from "fumadocs-core/search/server";

export const { GET } = createSearchAPI("advanced", {
  language: "english",
  indexes: source.getPages().map((page) => {
    const data = page.data as any;
    return {
      title: page.data.title ?? "",
      description: page.data.description,
      url: page.url,
      id: page.url,
      structuredData: data.structuredData ?? { headings: [], contents: [] },
    };
  }),
});
```
</instructions>
